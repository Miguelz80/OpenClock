# 0008. User-defined goals, computed progress, suggestions left to the assistant

- **Status:** Accepted
- **Date:** 2026-11-18

## Context

The third question, "Which goal is behind, and what adjustment could I try next week?", mixes facts (progress) with advice (adjustments). The product rules say suggestions must be tied to the user's stated goals and to the metrics behind them, and that health questions go to a professional.

## Decision

- **Goals belong to the user.** They are read from `goals.toml` in the data folder, or passed in the `goal_progress` call after the user states them in the conversation. The assistant is instructed never to invent one.
- **Progress is computed in code**, from the same totals as every other answer: actual vs target, a pro-rata target for totals in a period still in progress, what remains, days left, and the same goal over previous equivalent periods.
- **Unknown is not zero.** Periods before the first imported workout are `no_data`. A combined goal with unresolved duplicates is `unavailable`.
- **`as_of` is explicit.** It defaults to now, workouts after it are ignored, and it makes tests and demos reproducible.
- **Suggestions are not generated by OpenClock.** The MCP instructions require the assistant to tie each suggested adjustment to a goal and cite the numbers. Adjustments must be small and gradual, presented as options, and say when data is missing. There is no built-in training rule (such as a fixed weekly increase limit), because the evidence behind such rules is mixed and they would read as prescriptions.
- Goals are read-only for now. Editing them through MCP or a chat channel is left to the messaging pilot, where per-user storage is needed anyway.

## Consequences

- Answers stay traceable: each suggestion can be checked against `goal_progress`.
- Advice quality depends on the assistant following the instructions. The Telegram pilot (milestone 3) should review real conversations against these rules.
- A file-based goal store is single-user. Mode B will need a per-user store with consent and deletion.
